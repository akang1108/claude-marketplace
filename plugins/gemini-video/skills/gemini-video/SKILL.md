You are the `/gemini-video` skill. You generate short video clips using Google Gemini's Omni video model from a text prompt or an input image.

## Bootstrap (run before every invocation)

1. Require `uv` and the API key:
   ```bash
   command -v uv >/dev/null || { echo "Error: uv is not installed (https://docs.astral.sh/uv/)."; exit 1; }
   [ -n "$GEMINI_API_KEY" ] || { echo "Error: GEMINI_API_KEY is not set. Add it to your shell profile."; exit 1; }
   ```

2. Resolve the skill directory:
   ```bash
   SKILL_DIR="${CLAUDE_PLUGIN_ROOT}/skills/gemini-video"
   ```

## Invocation

```bash
uv run --script "$SKILL_DIR/gemini_video.py" --prompt "<prompt>" [--image <path>]... [--duration <seconds>] [--resolution 360p|720p|1080p|4k] [--aspect-ratio 16:9|9:16] [--output <filename>]
```

- `--duration`: whole seconds, 3-15 (default 10).
- `--resolution`: default 720p; 1080p and 4k are upscaled.
- `--aspect-ratio`: 16:9 (default) or 9:16 only.
- `--image`: repeatable, up to 6 images used as guides for the video.
  - Veo's separate frame-0 (`--image`) and subject-reference (`--reference`) modes no longer exist.
  - How an image is used is driven by the prompt, e.g. "using the drawing only as a guide for movement".
- Only pass `--resolution`, `--duration`, or `--aspect-ratio` when the user asks.
- The script tries `gemini-omni-1.2-flash`, then falls back to older Omni models if the newest returns 404.
  - The "Model:" line in the output says which one ran.

**IMPORTANT:** Do NOT pass `--output` unless the user explicitly provided a filename. The script automatically derives a human-readable filename from the prompt (e.g. "timelapse of clouds" → `timelapse-of-clouds.mp4`). Never construct a timestamped or otherwise generated filename yourself.

**Output location matters — do not redirect it.** The generated video is a deliverable the user asked for, not a temp file. Run the script from the working directory the user was already in *before* this skill was invoked — do not `cd` into a scratchpad/session/tmp directory first, and do not pass `--output` pointed at one, even if your environment nudges you toward a scratchpad for temp files. That guidance doesn't apply here: this output belongs next to the user, in their cwd.

Video generation is a single blocking request that can take a minute or more. Tell the user it is in progress, and report the saved filename when complete.

## Prompt Crafting — Image Input

Images are guides, not a fixed first frame. Say what the video should do with them.

- Describe action that starts immediately and continues throughout.
- Say how to use the image, e.g. "use the drawing only as a guide for movement, do not show the drawing in the final video".
- For a person in the photo, describe what they do: "A person smiles at the camera, leans forward, and says 'Hey everyone'".
- Dialogue works: write it as `...saying "Hello, welcome to my channel"`.
- Avoid static language: no "remains", "sits", "stands still", "poses".
- Negative prompts are not supported; write "Do not show X." in the prompt instead.

When the user gives a vague prompt like "make a video of this person talking about X", expand it into a full active-motion prompt following the rules above before invoking the script.

## Usage Examples

```
# Generate a video from a text prompt
/gemini-video a timelapse of clouds moving over a mountain

# Animate an image
/gemini-video --image sketch.jpg animate this as a river flowing downstream

# Person in photo
/gemini-video --image photo.jpg make this person introduce themselves and wave hello

# Vertical 1080p, 5 seconds
/gemini-video a sunset over the ocean --aspect-ratio 9:16 --resolution 1080p --duration 5

# Custom output filename
/gemini-video a sunset over the ocean --output sunset.mp4
```

## Voice / Audio Limitations

Audio is generated by default and can be described in the prompt. There is no voice identity or voice cloning support:

- You **cannot** provide a reference video or audio sample to match a person's voice
- You **cannot** select a specific voice for a person in the video
- Dialogue in the prompt (e.g. *"saying 'Hello'"*) works, but the model picks the voice

If you need the subject's real voice, the workaround is post-processing: synthesize speech separately (e.g. ElevenLabs, or the Gemini TTS API with `ReplicatedVoiceConfig` + a WAV sample), then replace the audio track with `ffmpeg`.

## After Running

- Report the saved `.mp4` filename and its full path.
- Also report: model used, duration, resolution, and file size (all printed by the script after "Saved:").
- Let the user know they can open it with any video player.
- On error, print the stderr output from the script clearly.
